In your browser, right here

The whole engine is the page: the planner, the image analysis, the fidelity audit, the clip measurements and the final render.

  1. Open the tool

    It is a static page on GitHub Pages. There is nothing to sign into and nothing to wait for.

  2. Create a project and drop in your renders

    One to eight images of one project. They are read in the tab and never uploaded anywhere.

  3. Name the finishes, state the location, approve the plan

    The plan is deterministic, so the same intake always gives the same shot list and you can predict what a change will do.

  4. Generate, measure, sequence, render

    Out of the box it uses a demo generator that costs nothing and still exercises every gate, so you can take a project all the way to a finished film before deciding whether to spend anything.

Everything stays on your machine. Projects, renders, generated stills, clips and films live in this browser’s own storage. No server ever sees them. That is the good news and the catch: clearing site data for the address erases the lot, and another device will not see your projects. Download the film and the stills pack when a project is done, or export the whole project as one ZIP from the project list and import it on any machine.
Keep the tab in front while video is being written. Clips and the final film are recorded in real time, so a 45-second film takes about 45 seconds. A browser freezes animation in a background tab, which would record a still picture over a running clock, so the tool throws that render away rather than hand you a frozen film. Run it and let it run.

What the browser can and cannot encode

The film is recorded from a canvas, so its format is whatever the browser will encode. Chrome, Edge and Safari on a normal desktop write H.264 in an MP4, which is what a client can drop into a slide deck. Firefox and some builds of Chromium have no H.264 encoder and write VP9 in a WebM, which plays in any browser but not in QuickTime, PowerPoint or most editors.

The tool does not guess at this. It records a fraction of a second, reads the bytes back, and tells you in Settings and on the render page exactly what it produced. A file is never given an .mp4 name for something an MP4 cannot hold.

If you land on WebM and need an MP4, the Python server below renders with ffmpeg and always writes H.264. So does running the film through any converter.

Using a paid API, and why that needs a server

This is the one thing a static page genuinely cannot do for you.

A web page can only read a reply from another site when that site marks the reply readable, which is what the CORS rules are. An API that authenticates with a secret key normally refuses, precisely so a key cannot be used from a web page. That is a sensible rule and it is not something this tool can wave away.

So the tool does not pretend. Paste a key under Settings, press Test the key, and it says plainly whether calls from your browser get through. If they do, real generation works from the page. If they do not, nothing is charged and you have two honest options.

  • Run the Python server from the repository. It makes the same calls from the server side, where the restriction does not apply, and renders with ffmpeg. Same interface, same gates, same measurements.
  • Point the base URL at a relay you control that adds the CORS headers. Only do this with a relay that is yours: anything in between sees your key.
The key lives in this browser. A static page has no server to keep a secret on and no way to check a password before handing out its own source, so there is no access lock and there is no point pretending otherwise. The key is stored in this browser’s storage on this device, never sent anywhere by this page, and never put in the repository. If the machine is shared, use the server version instead.

The server version

Same app, FastAPI and ffmpeg behind it. Use it for a paid key, for H.264 output, or for a shared address.

On GitHub, in a Codespace

GitHub’s own container host runs it unchanged, with an HTTPS address and nothing installed locally.

Open in a Codespace
  • The forwarded port is private to you by default, which is the right default for something holding a paid key. To share a link, open the Ports panel, right-click port 8000, choose Port Visibility, then Public.
  • A personal GitHub Free account includes about 120 core-hours a month plus 15 GB of storage. A codespace stops after 30 minutes idle; storage persists and batches resume where they stopped, so nothing is paid for twice.
  • Storage keeps billing while a codespace exists, even stopped. Delete it when a project is finished.

Always on

For an address that is up without anyone opening anything, deploy the same repo to a container host. On Render, sign in with GitHub, choose New, then Blueprint, connect the repository and pick the branch.

Do not use the one-click Deploy to Render button for this repo. It is known to fail with “No render.yaml file found on main branch” when a repository’s default branch is not main, which is the case here. Use the dashboard flow, where the branch is a dropdown.
Do not put a paid API key on a free plan. A free instance sleeps after about fifteen idle minutes, and the server does its work in background threads rather than holding the request open. A long batch only survives while a tab is polling it, and a free plan has no persistent disk, so clips you already paid for are lost when it suspends.

On your own machine

git clone https://github.com/argaurshar/Images-to-video-with-ref-video
cd Images-to-video-with-ref-video
pip install -r requirements.txt
./run.sh            # http://127.0.0.1:8000

Or with Docker:

docker build -t archviz .
docker run -p 8000:8000 -v archviz-data:/data archviz

Run a single worker. The batch job registry lives in the process, so a second worker would not see a running job and could start a duplicate batch and pay twice.

Start on the demo generator either way. It costs nothing and still runs the planner, the fidelity audit, the QC suite and the render for real, so you can rehearse a whole project before spending anything.
