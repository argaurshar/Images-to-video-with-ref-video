Run it

A Codespace on GitHub, an always-on host, or your own machine. In every case the API key is set inside the app, not in a dashboard.

Open in a Codespace

On GitHub, in a Codespace

The app runs unchanged on GitHub’s own container host. Nothing installed.

  1. Open a codespace

    Use the button above, or from the repo page choose Code, the Codespaces tab, then Create codespace.

  2. Wait for the build

    GitHub builds the container, installs the dependencies and starts the server on port 8000. The first build takes a few minutes because it installs OpenCV.

  3. Open the forwarded URL

    Click the app.github.dev link it shows you.

  4. Claim it, then add your key

    Set an access code, then paste your Freepik key under Settings and press Test the key.

Private by default. The forwarded port is visible only to you, signed in to GitHub. That is deliberate, because the instance holds a paid API key. To send a client a link, open the Ports panel, right-click port 8000, choose Port Visibility, then Public.

What it costs

A personal GitHub Free account includes about 120 core-hours a month, roughly 60 hours on the default two-core machine, plus 15 GB of storage.

  • A codespace stops after 30 minutes idle. A long clip batch is interrupted if you close the tab. That is survivable here: storage persists and batches resume where they stopped, so nothing is paid for twice.
  • Storage keeps billing while a codespace exists, even stopped. Delete it when a project is finished.

Always on, for an address that stays live

A Codespace is for working on projects yourself. For a URL that is up without anyone opening anything, deploy the same repo to a container host.

Render

Sign in with GitHub, choose New, then Blueprint, connect the repository and pick the branch. Render reads the blueprint in the repo and builds the container.

Do not use the one-click Deploy to Render button for this repo. It is known to fail with “No render.yaml file found on main branch” when a repository’s default branch is not main, which is the case here. Use the dashboard flow, where the branch is a dropdown.
Do not put a paid API key on a free plan. A free instance sleeps after about fifteen idle minutes, and this app does its work in background threads rather than holding the request open. A long batch only survives while a tab is polling it, and a free plan has no persistent disk, so clips you already paid for are lost when it suspends.

Railway

Around $5 a month on the Hobby plan, cheaper than Render’s paid tier. The repo ships a railway.json so the build is described. The difference is that Railway does not create the disk for you: after the first deploy you add a Volume mounted at /data and set ARCHVIZ_DATA_DIR=/data.

On either host, 512 MB of RAM is tight for ffmpeg and OpenCV holding 1080p frames. If a render dies with an out-of-memory error, raise the instance size rather than shortening the film.

Setting the key, and locking the instance

Start on the mock provider. It costs nothing and still runs the planner, the fidelity audit, the QC suite and the ffmpeg render for real, so you can rehearse a whole project before spending anything.

On your own machine

git clone https://github.com/argaurshar/Images-to-video-with-ref-video
cd Images-to-video-with-ref-video
pip install -r requirements.txt
./run.sh            # http://127.0.0.1:8000

Or with Docker:

docker build -t archviz .
docker run -p 8000:8000 -v archviz-data:/data archviz

Run a single worker. The batch job registry lives in the process, so a second worker would not see a running job and could start a duplicate batch and pay twice.
